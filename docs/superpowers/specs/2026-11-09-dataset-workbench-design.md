# 训练数据页重设计：数据集工作台

> 2026-11-09。用户授权「大胆重构，推翻现有设计，可调整前后端接口」，设计决策由实现者做出，下文标注为「我的判断」。

## 1. 为什么重做

旧页面是一个「伪向导」：画了「配置 → 检查 → 导出」三步与编号，但三块同时可见、同时生效，进度条永远停在第 1 步；同一组筛选条件在页面上重复展示三次；真正要导出的对话样本藏在默认折叠的面板里，且只能看第 1 条；评分分布只统计阈值以上的部分，看不出阈值砍掉了多少；导出按钮在页面最底部，调筛选时看不到。

排查中还发现两个后端缺陷：

1. **预览计数与导出条数不一致**：`PreviewExport` 以 `jsonb_array_elements_text(model_ids)` 展开后逐行计数，一个会话用了 N 个模型就被计 N 次（评分分布同样重复计数）；且无模型的会话被 `model_ids IS NOT NULL` 排除，而导出并不排除。页面说「将导出 1,284 条」，实际导出的条数可能不同。
2. **多选模型是「同时包含」语义**：`model_ids::jsonb @> ?` 要求会话同时用过全部所选模型，与勾选列表「任选其一」的通常预期相反，多选越多结果越少。

## 2. 设计：数据集工作台（参考 Databricks Catalog Explorer / SQL 编辑器的心智）

筛选条件就是一个查询，结果实时可见，数据本身是主角，主操作始终在手边。没有步骤。

```
┌ 结果栏（吸顶）──────────────────────────────────────────────────────────┐
│ 1,284 段对话   23,410 条消息 · 平均 18.2 条/段 · 31% 含工具调用   [导出 JSONL] │
│ ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔ 导出进度细线（仅导出中）                                │
└──────────────────────────────────────────────────────────────────────────┘
┌ 配方栏（20rem）──────────┐ ┌ 样本检查器 ──────────────────────────────────┐
│ 时间范围                  │ │ ‹ ›  随机   第 3 / 1,284 段     [对话 | JSON] │
│ 质量门槛                  │ │ #8812 · 评分 4 · gpt-5 · 打开会话             │
│  ▁ ▃ ▅ █ ▇ ▂  直方图即选择器│ │ system     …                                │
│  未评分 1 2 3 4 5          │ │ user       …                                │
│  保留 1,284 / 2,010        │ │ assistant  思考（可展开） + 正文 + 工具调用      │
│ 模型（任一）              │ │ function   …                                │
│  ☑ gpt-5      812 ▮▮▮▮    │ │ tools      3 个工具定义（可展开）              │
│  ☐ claude     401 ▮▮      │ └─────────────────────────────────────────────┘
│ 重置                      │
└──────────────────────────┘
```

- **结果栏是唯一的「当前结果」展示处**：匹配会话数、消息总数、平均每段消息数、含工具调用占比、导出按钮。旧页面里三处重复的筛选摘要全部删除。
- **质量门槛 = 直方图本身**：六根柱（未评分、1–5 分）同时是单选按钮，点第 k 根表示「保留 k 分及以上」，点「未评分」表示不限。阈值以下的柱变淡，底部写「保留 X / Y」。直方图统计时**不应用评分条件**（分面语义），所以拖动阈值时被砍掉的部分始终可见。
- **模型 = 分面勾选列表**：每个模型带会话数与比例条，计数时**不应用模型条件**（分面语义），未勾选的模型也能看到「勾上会多出多少」。多选为「任一」语义。模型数量超过 8 个时出现搜索框。模型选项直接来自预览接口，不再单独请求 `session/option/list`。
- **样本检查器默认打开，是首屏主角**：逐条翻看匹配的会话（上一条 / 下一条 / 随机），默认按 ShareGPT 的 `from` 字段分行渲染（角色名直接显示字段原值 `system/user/assistant/function`，即文件里的真实内容），`<think>` 段落折叠展示，`function_call` 单独成块；可切换到格式化 JSON 查看原始行。头部显示会话 ID、评分、模型、创建时间，并链接到会话详情。
- **导出原地完成且可取消**：点击后按钮变「取消」，结果栏底边出现进度细线并显示「已写入 X / Y」；完成后 toast，并在结果栏留一行「已下载 文件名」。
- **空态有下一步**：无匹配时样本区显示说明，若有筛选条件则给「清除筛选」。

### 视觉（我的判断）

属于 Operate 模式，沿用控制台现有 token（anthropic / moonshot 两套主题、Maple Mono CN、`font-display` 数字），不引入新色板。表现力只花在一处：直方图选择器（柱高、阈值淡化、选中柱的 primary 色）。其余保持克制：不用卡片堆叠，配方栏用细分隔线分段，样本区是一块连续的阅读面。

### 响应式

`lg` 以下配方栏在上、检查器在下，结果栏仍吸顶；手机上结果栏的次要指标收起，只留会话数与导出按钮。

### 实现中的偏差（实测后调整）

- **时间范围移到页头右侧**（与仪表盘一致）：`TimeRangePicker` 实测宽 478px，放不进 20rem 配方栏；它本来就是整页的范围，放页头语义更准。
- **模型比例条改为名称下方的细线**：最初做成整行背景色块，实测读起来像一排长短不一的高亮药丸，干扰扫读。
- **只置顶「已勾选但当前范围内为 0」的模型**：全部置顶会让刚勾上的行从指针下跳走；只置顶 0 计数的那类，筛空时原因一眼可见，又不打扰正常勾选。
- 结果栏在无匹配时隐藏次要指标（全是 0 只是噪音）。

## 3. 接口契约变更

| 接口 | 变更 |
|---|---|
| `GET /dataset/preview` | 响应改为 `totalSessions`（按会话去重，与导出条数一致）、`totalMessages`、`toolSessions`、`scoreHistogram`（不应用 `minScore`，键 `0` 表示未评分）、`modelFacets`（不应用 `modelIds`，每个会话对每个模型计一次）。删除 `scoreDistribution` / `modelDistribution`。 |
| `GET /dataset/sample` | 由「拉全量行再取下标」改为 SQL `COUNT` + `OFFSET/LIMIT 1`；响应新增 `score`、`modelIds`、`createdAt`。越界 offset 仍钳到最后一条。 |
| `GET /dataset/export` | 不变（模型筛选随共用的 `applyExportFilter` 改为「任一」语义）。 |
| 模型筛选 | 三个接口统一改为「任一所选模型」：`EXISTS (SELECT 1 FROM jsonb_array_elements_text(model_ids::jsonb) AS m(model) WHERE m.model IN ?)`。 |

前端是这些接口的唯一消费者，同 PR 同步修改 `types.ts`。

## 4. 不做

- 不做导出历史、导出格式选择、数据集版本管理（无需求）。
- 不保留任何步骤 / 向导视觉。
- 不新增依赖。

## 5. 验证

- Go：postgres DryRun 守护预览三条 SQL 的形态（总数查询不展开模型数组；直方图查询不带评分条件；分面查询不带模型条件；模型条件是 `EXISTS … IN`）；sqlite 真实执行守护样本单条读取的 offset、钳位与归属三态语义。
- Web：`lib/dataset.ts` 纯函数（ShareGPT 行解析、保留数计算、文件名）vitest；`npm run lint && npm test && typecheck`；构建产物上用无头浏览器在 390 / 1280 / 1728 三档 × zh/en/ja 检查无横向溢出。
